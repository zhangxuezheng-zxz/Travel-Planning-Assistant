# 行程中的景点与活动

新建行程的景点选择仍只读取数据库目录。完成创建后，在行程详情点击“添加”，可以选择：

- 景点：仅检索当前城市数据库中的未添加景点；选中后显示坐标与地图预览，追加到指定日期，保留已有安排并避开活动时段。容量不足时拒绝写入。
- 活动：使用高德搜索当前城市的餐厅、咖啡馆、商场等 POI；选中后显示实际位置，并可设置活动名称、日期、开始时间、时长及备注。

活动以独立卡片显示在每日安排中，与景点一起参与地图标记和站间路线预览。活动时间固定，由用户编辑；高德路线显示交通预览，若前后预留不足会提示调整，不会把估算宣称为已确认行程。

活动可修改地点、时间和备注，也可从当前行程删除。数据库景点可从行程中移除，公共景点资料不会被删除。未保存景点调序时，先保存或取消调整，再编辑活动。

出游模式会按当天景点和活动共同推进；活动可标记完成并恢复进度，完成活动不会自动伪造数据库景点足迹。景点调序与活动时段冲突时，预览会提示冲突并禁用保存；排不下的景点仍保留地图站点资料，不会因缺少预览时间而让页面崩溃。

## 持久化与升级

运行 `npm run db:migrate` 应用 `202611260001_trip_activities.js`，再重启后端。活动存储在 `trip_activities`，通过 `trip_id` 归属具体行程；删除行程时级联清理。活动不会写入 `places`，也不混入自动推荐的 `selectedPlaceIds`。

`Trip.activities` 返回活动 ID、标题、备注、日期、时间、时长、高德 POI ID、地点名、地址及 GCJ-02 坐标。只允许已规划行程添加活动；既有行程默认空活动数组。

活动保存前，服务端按 POI ID 查询高德详情，不采信客户端自报坐标；修改同一地点的标题或时间时使用已保存的地点。景点与活动的写操作都校验归属、行程版本和时间，失败不会部分写入或覆盖其他账号数据。

明确允许重新规划会替换每日安排并清空活动，界面已提示。仅修改标题、普通保存、调序不会主动清空活动；调序若与活动冲突，会拒绝保存并保留原安排。

## 接口

均需 Bearer 登录鉴权，路径以 `/api` 开头。

| 接口                                                          | 用途                                                 |
| ------------------------------------------------------------- | ---------------------------------------------------- |
| GET /trips/:id/activity-locations?keywords=...                | 高德地点搜索，限定行程城市和账号                     |
| POST /trips/:id/activities                                    | 新增活动，返回最新 Trip                              |
| PATCH /trips/:id/activities/:activityId                       | 编辑活动，返回最新 Trip                              |
| DELETE /trips/:id/activities/:activityId?expectedRevision=... | 删除活动，返回最新 Trip                              |
| POST /trips/:id/scenic-stops                                  | 从数据库追加景点，传 expectedRevision、placeId、date |
| DELETE /trips/:id/scenic-stops/:placeId?expectedRevision=...  | 从行程中移除数据库景点                               |

新增/修改活动传入 `expectedRevision、title、notes、date、startTime、durationMinutes、poiId`。时长 5～720 分钟，不能跨越当天；每行程最多 100 个活动。过期版本返回 409，活动时间冲突返回 422，错误输入返回 400。

## 高德与测试

后端需要 `AMAP_WEB_SERVICE_KEY`；前端底图沿用 `VITE_AMAP_WEB_KEY`。Key 保留在私有环境配置中。高德未配置或调用失败时明确报错，不回退成伪造地点。

关键词搜索使用高德 v5 `place/text`，以 `region` 和 `city_limit=true` 限定城市；保存时使用 POI 详情核对地点。参考[高德搜索 POI 2.0 官方文档](https://lbs.amap.com/api/webservice/guide/api/newpoisearch)。

```powershell
npm run test:activities
```

该命令构建 API、迁移专用 `TRIP_TEST_DATABASE_URL`（库名须以 `_test` 结尾），运行真实 HTTP/PostgreSQL 的增删改、越权、并发、冲突、级联与重新规划测试。高德适配器使用确定性测试响应，另通过浏览器验证真实高德搜索、选中定位、卡片编辑和路线显示。测试账号及行程会按本次测试范围清理。

合并当前 `main` 后沿用其邮箱验证码注册、登录会话、个人资料和首次偏好引导。活动测试在专用库和 `NODE_ENV=test` 下显式使用本地验证码模式，先请求验证码，再通过真实注册接口创建已验证账号，同时确认不带验证码的注册被拒绝；不会发送真实邮件，也不会绕过生产注册校验。

CI 分别创建行程、登录两个隔离测试库，运行 `npm run test:activities` 和 `npm run test:auth`。本地登录集成测试另需配置 `AUTH_TEST_DATABASE_URL`；真实收发邮件配置仍见 [登录与资料说明](auth-profile.md)。

部署到测试服务器时需同步更新前后端并执行数据库迁移；仅更新前端不会升级后端。登录业务实现保持与 `main` 一致，此次合并只调整测试接入和脚本配置。
