# 10.27项目分工与需求对齐会 

## 一、会议概况
- **会议主题**：项目分工与需求对齐会
- **核心目标**：明确首发城市、梳理核心功能模块接口依赖、确定前端开发执行策略
- **关键参与人**：孙佳艺、章学政、刘妍、赵福涛

---

## 二、核心决议与讨论要点

### 1. 项目文档与工具规范
- 会议全程启用 AI 纪要工具，确保讨论内容完整留痕。
- **README 文档**需清晰说明每个人的功能职责及代码存放路径；代码提交分支由前端负责人（章学政）最后合并，统一处理端口冲突。
- 团队决定新增一份 **Markdown 接口约定文档**，用于整理并存放各模块的接口定义与约定。

### 2. 核心功能与页面规划
- **首发城市**：首个版本确定以 **北京市** 为例进行开发与测试（北京景点多、共识度高，但需注意团队熟悉度极高易暴露产品短板）。
- **四大功能板块**：
  - **首页展示**：当前位置显示、景点推荐、聊天框交互。
  - **行程规划**：历史与现代路线规划，支持右上角加号创建新行程。
  - **旅行地图**：点足迹功能，展示景点打卡记录（即“地图手账”模块）。
  - **设置页面**：常规应用设置功能。

### 3. 前后端分工与接口依赖
- **后端接口先行**：后端需先明确接口输入输出并与前端对齐，前端方可开展后续工作。
- **首页实现方案**：
  - 定位获取当前所在城市。
  - 聊天框采用 **固定下拉选项**（如“出行”“饮食”），限制提问范围，降低大模型调用复杂度。
- **行程规划 API 策略**：
  - 行程可视化绘制 **直接调用高德地图 JS API**，无需大模型介入。
  - 行程创建规则交由大模型生成。
- **数据库与数据管理**：
  - C 模块负责人（赵福涛）负责初始数据库搭建，**先录入北京经典 5A/4A 景区数据**供打卡使用。
  - 预设经典景区（如长城等）作为固定打卡点，避免动态加载导致画面混乱。

### 4. 前端开发排期与协作
- **启动顺序调整**：因后端界面未定稿，前端暂缓开发首页与行程规划，**优先从注册登录页切入**。
- **强绑定协同**：前端需跟随 D 模块负责人的需求进度，同步开发 **旅行地图（手账）页面**，确保地图点位与数据存储逻辑一致。
- **跨模块互助**：若个人任务量较轻，需主动协助任务繁重的队友完成代码编写。

### 5. 地图风格与视觉设计
- **风格备选**：针对真实地图信息杂乱问题，考虑多风格适配。
  - **灰白风格**：参考 TT 项目中已有的灰白地图样式，可直接复用资源。
  - **漫画风格**：通过前端定制多个风格选项供用户选择。
- **预设点位优化**：将经典景区写入数据库作为固定打卡点，保证界面清爽。

## 四、会议总结与后续方向
本次会议高效完成了项目分工与核心需求的对齐，团队确立了“**先跑通最小可用版本，再灵活迭代**”的敏捷开发思路。通过明确首发城市（北京）、四大功能模块边界、前后端接口依赖关系以及前端优先开发路径，为后续开发奠定了清晰基础。

2. 前端按优先级推进注册登录页及旅行地图页面，后端同步明确接口定义。
